# FIT uploads and shared Strava activities

Athletes open Activity → Add activity. Choose one .FIT workout file (maximum 10 MB), or paste a Strava activity/share link. Notes are optional. Submissions stay pending until reviewed; the athlete sees the decision and rejection reason on the same screen.

On iPhone, open Sage once while signed in, then use Strava → Share → Sage (enable Sage under More if necessary). The native share extension submits the link and an optional note directly to the same private queue. An expired sign-in prompts the athlete to reopen Sage. It reads the existing session from the app's default keychain group; no App Group entitlement or Strava developer API is required. Actual sharing from Strava on the physical phone still needs a user check.

Admin opens Workouts → Review FIT uploads & shared posts. FIT metrics are parsed server-side and cannot be replaced by client-provided values. Strava links are evidence: admin opens the linked activity and confirms name, timezone-aware start time, sport, moving duration and optional distance before approval. Private activities must be accessible to the reviewing admin in Strava. Approval imports one workout and runs the existing approved-only scoring rules. Rejection removes its contribution; stale reviews are rejected and existing workout review decisions synchronize with the submission queue. Similar already-imported workouts are blocked to avoid double counting.

FIT imports preserve recorded indoor distance, HR, speed, elevation and GPS when present. Approved FIT workouts use their uploaded streams for charts across platforms, and the native route map displays recorded GPS. Indoor rides do not acquire a fabricated outdoor map. Only single-workout supported-sport FIT files are accepted; corrupt CRCs and invalid times are rejected. Distance can fall back to the file's cumulative distance records if its session summary omits distance.

Files live in the private `workout-files` bucket with owner-folder uploads and owner/admin reads. Server ingestion validates the authenticated athlete, path, file size and decoded metrics. Only service-role ingestion can create submissions; client writes to status/metrics are revoked. Exact file hashes and canonical Strava links are deduplicated; duplicate/invalid unreferenced uploads are cleaned up. Notes never trigger automatic fetching of arbitrary external URLs. Review events stay private.

Backend migration: `20261009075245_workout_submissions.sql`. Function: `submit-workout` (gateway JWT verification disabled, handler explicitly validates the access token using `getUser`). Frontend contains no service key.

After regenerating iOS with Expo prebuild, run `npm run ios:share`, then install pods. `npm run ios` and `npm run ios:preview` also configure the extension before building. Source is under `native/SageShare`; the setup script creates the Xcode target, generated public backend configuration, shared keychain entitlement, frameworks and embedding phase. CocoaPods' `xcodeproj` Ruby gem is required. Existing free-team provisioning successfully signed and installed both targets on this Mac; distribution to other users follows normal Apple build distribution requirements.

Validation: TypeScript check; web export; SDK-generated indoor FIT fixture (distance, HR, speed and CRC rejection); PGlite approval/rejection, service-only ingestion, link metrics requirement, duplicate and stale-review checks, private owner access and review synchronization; live seeded-account API checks and invalid-link response validation; iPhone Release build and device installation. No real athlete workouts were created by the verification scripts. Security advisors reported existing unrelated database warnings and no warning naming the new submission objects. Physical Strava share-sheet interaction and real-file picker UI were not automated.
