# Record workouts directly in Sage

Open Activity → Record a run, walk or ride. Choose a sport, allow precise location, then Start. The live screen shows the recorded route, distance, active time, elapsed time and average pace (speed for rides). Pause/Resume controls exclude paused time and separate route segments. Finish → Save & submit for review sends the automatically calculated metrics to the existing admin queue. GPS alone cannot measure heart rate or calories; those are not invented.

The installed native app supports background recording using Expo Location and TaskManager. Allow Always/background location for screen-lock recording; if permission is denied, foreground recording is available and automatically pauses when Sage leaves the foreground. Location sampling stops on Pause, Finish, Discard or switching accounts/signing out. Avoid force-quitting during a workout: mobile operating systems can stop background location. Missing GPS gaps are left separate and never bridged into distance. Mobile browser recording is not enabled; submitted routes can be viewed in the web app.

One unsent workout per account is stored locally in the app's private document directory. Back navigation does not erase it. Offline finish keeps the draft; submit when connected. The finished recording survives app reopening until successful submission or explicit discard. Submission retries use the original recording ID to prevent duplicate posts.

Raw recording documents include timestamped GPS accuracy, coordinates, active intervals and a recording ID. The authenticated endpoint reads the athlete's private uploaded JSON file, verifies its owner and size, and recalculates metrics from samples. Client-provided distance/duration totals are ignored. Samples over 50 m accuracy, invalid coordinates/timestamps, implausible speed jumps and paused samples are excluded. Gaps over 30 seconds start a separate segment. Small movement below the accuracy-based floor is treated as GPS drift. GPS distance and elevation are estimates and depend on signal quality.

Admin → Workouts → Review recordings, uploads & shared posts includes a route preview and automatically filled metrics. Approval uses the existing score rules; rejected workouts do not count. GPS totals cannot be replaced through the review form. Routes remain private to their athlete and admin. Approved activities expose their own recorded streams to the existing activity charts and maps.

Implementation: `lib/gpsRecording.ts` and its exact shared server copy hold pure calculation logic; `lib/gpsRecorder.ts` registers the headless location task at root startup, serializes local draft writes and manages location lifecycle. Platform web overrides avoid native task APIs. `hooks/useGpsRecorder.ts` coordinates screen state and submission. `20261009084814_gps_recording.sql` extends the existing submission/approval workflow. The `submit-workout` function validates authenticated ingestion. Native permissions are configured both in app.json and the existing iOS Info.plist; Expo TaskManager 12.0.6 matches SDK 52.

Validation: pure GPS calculation tests (pauses, jumps, bad accuracy, missing signal, stationary drift, rejected unfinished/future sessions, Unicode uploads and client/server parity); mocked native lifecycle tests (persistent drafts, task samples, account isolation, start/pause/resume/finish/discard and foreground fallback); PGlite service-only ingestion, recorded-metric override denial, approval/rejection and private route access; live seeded-account API checks, invalid GPS ownership denial; TypeScript check, web export and iPhone Release build. Security advisors reported 20 pre-existing warnings and none naming the recording/submission objects. No real athlete records were created by tests. A real outdoor and screen-lock recording test on the physical phone remains necessary; simulated tests cannot establish physical GPS accuracy or battery use.
